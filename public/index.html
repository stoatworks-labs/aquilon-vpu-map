Aquilon VPU Map

Every layer on a LivePremier costs physical mixing hardware. This shows where that hardware actually went — read live from the device over AWJ.

Reads only — this tool never writes to the device. AWJ is TCP 10606, so the read is made by this app's own server, not from the browser.

Chassis

Four processors of sixteen mixers each. Colour is the screen a mixer serves; the number under it is which slice of that screen it carries.

Link grid

Each VPU as the manual draws it: eight layer links in from the left, eight output links out through the top and bottom. A layer occupies a block sized by its capacity, and one spread past the scaling-engine boundary takes a second layer link.

What each screen costs

A layer is not one mixer — it is a run of them, one per slice. The widest layer on the box is the one that decides whether a show fits.

Staged changes

The device keeps a running allocation and a staged one. These mixers differ between the two — this is what applying the pending configuration would cost.

Detail

Every fitted mixer, as reported. All of these properties are read-only on the device.

What a VPU mixer is

A VPU mixer is the physical mixing and scaling resource a LivePremier allocates to a screen and layer. An Aquilon has up to four processors of sixteen mixers — 64 in total, though most chassis are part-populated.

A layer too wide for a single mixer is split across several, each carrying one slice. That is why an eight-slice native layer can consume an entire processor board on its own, and why layer count alone never tells you whether a configuration will fit.

The device reports this map read-only, under preconfig/resources/{current|new}/status/mapping. Everything this tool shows is that map.
